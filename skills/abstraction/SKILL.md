# 抽象化

具体と抽象を行き来して、個別の事例からほかでも使える型を取り出し、抽象的な言葉には具体の中身を持たせる。

## いつ使うか

- 個別の事例から、ほかでも使える型や原則を取り出したいとき
- 社内の事例やドキュメントを、ほかの組織でも使える形にしたいとき（汎用化）
- 文章や目標が「ふわっとしている」と言われたとき
- 読み手に合わせて、話の抽象度を変えたいとき

主張と根拠のつながりは `logical-thinking`、分け方と並べ方は `structuring` を使う。

## 1. 抽象化する

やること:

1. 複数の具体例を並べる。1 つしかなければ、似た例を探すか、型にするのを待つ
2. 例ごとに、共通点と相違点を書く
3. 共通点だけを残して、名前を付ける
4. 取り出した型を、元の例とは別の場面に当てはめてみる。当てはまらなければ、まだ元の例に寄っている

守ること:

- 相違点を捨てる前に、それが結果を左右していないかを確かめる。左右しているなら、型の条件として残す

## 2. 汎用化する

やること:

1. 特定の組織・人・出来事に固有のものを書き出す。名前、数字、制度、日付、その場限りの段取りなど
2. 固有のものを外す。外したところは、役割や条件の言葉に置き換える（例: 人の名前 → 決める人）
3. 外すと意味が通らなくなる部分は、その事例に固有の話として扱い、型には入れない
4. 外したあとの文を、事情を知らない人が読んで使えるかを確かめる

守ること:

- 公開できない情報が残っていないかを、外したあとにもう一度確かめる

## 3. 具体化する

やること:

1. 抽象的な言葉に、具体例を 1 つ添えられるかを確かめる。添えられないなら、その言葉はまだ中身が決まっていない
2. 「誰が、何を、どの状態にするか」を書けるところまで下ろす
3. 読み手が普段使う言葉で言い直す

守ること:

- 新しい言い回しで抽象をごまかさない。読み手に伝わらない言葉は、具体に戻して言い直す
- 例を並べすぎない。例は読み手の考えを、その例の範囲に狭める

## 4. 抽象度を選ぶ

やること:

1. 読み手が何を知っていて、何をしたいのかを確かめる
2. 結論は抽象で、根拠と例は具体で書く
3. 判断を求める相手には抽象度を上げ、手を動かす相手には下げる

## 5. 点検

書き終えたら、次の型に当てはまるところがないかを見る。

| 型 | 見分け方 | 直し方 |
| :--- | :--- | :--- |
| 1 つの例から一般化している | 型や原則の裏付けが、1 つの事例だけ | 別の事例に当てはめて確かめる。足りなければ、その事例での話にとどめる |
| 抽象語だけで具体がない | 「品質を高める」「連携を強化する」で止まっている | 誰が、何を、どの状態にするかを書く。具体例を 1 つ添える |
| 伝わらない言葉を使っている | 書き手が作った言い回しや略語が、定義されずに使われている | 読み手が普段使う言葉に言い換える。言い換えられなければ定義を書く |
| 固有のものが残っている | 汎用化したはずの文に、特定の組織の名前や制度が残っている | 役割や条件の言葉に置き換える |
| 具体に寄りすぎている | 例の細部が多く、何が言いたいのかが見えない | 一番言いたいことを抽象で冒頭に置き、例は 1 つに絞る |
