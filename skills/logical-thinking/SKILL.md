# 論理的思考

考えを、他の人が同じ道筋で追える形にする。道具は 3 つ。主張と根拠をつなぐこと、目的に合った軸で分けること、抽象と具体を行き来すること。

## いつ使うか

- 説明・提案・設計の考えを組み立てるとき
- 文章や資料の筋が通っているかを点検するとき
- 個別の事例から、ほかでも使える型や原則を取り出したいとき（汎用化）
- 情報が多く、どう分ければよいか迷うとき

何を解くかを決めるところは `problem-framing`、根拠が事実として正しいかは `fact-verification`、文章の表現は `technical-writing` を使う。

## 1. 主張と根拠

やること:

1. 一番言いたいことを一文で書く。文末まで言い切る
2. 主張を支える根拠を並べる
3. 上から下へ「なぜそう言えるか」、下から上へ「だから何が言えるか」と読み、両方向につながるかを確かめる
4. 読み手と共有していない前提を書き出す。書かれていない前提は、読み手には飛躍に見える

守ること:

- 根拠に、事実と解釈を混ぜない。解釈を根拠にするなら、その元の事実も書く
- 根拠から言える範囲を超えて主張しない。超えるなら、主張のほうを弱める

## 2. 構造化

やること:

1. 何のために分けるかを先に決める。目的が決まらないと、軸も決まらない
2. 分ける軸を選ぶ。よく使う型は次の 4 つ
   - 要素: 構成するもので分ける
   - プロセス: 時間や手順で分ける
   - 対になるもの: 内と外、量と質、事実と解釈など
   - 2 軸: 2 つの軸の組み合わせで分ける
3. 同じ階層の項目が、同じ軸で分かれているかを確かめる
4. 漏れと重なりを確かめる。「その他」が大きくなったら、軸が目的に合っていない
5. 同じ階層に並べる数を絞る。多ければまとめて、一段上の項目をつくる

守ること:

- 網羅を目的にしない。目的に効かない枝は落とす
- 抽象度の違うものを、同じ階層に並べない

## 3. 抽象化と具体化

やること:

1. 抽象化: 複数の具体例を並べ、共通点と相違点を書く。共通点だけを残して名前を付ける
2. 取り出した型を、元の例とは別の場面に当てはめてみる。当てはまらなければ、まだ元の例に寄っている
3. 具体化: 抽象的な言葉には、具体例を 1 つ添えられるかを確かめる。添えられないなら、その言葉はまだ中身が決まっていない
4. 読み手に合わせて抽象度を選ぶ。結論は抽象で、根拠と例は具体で書く

守ること:

- 汎用化するときは、特定の組織・人・出来事に固有のもの（名前、数字、制度、日付、その場限りの段取り）を外す。外すと意味が通らなくなる部分は、その事例に固有の話として扱う
- 新しい言い回しで抽象をごまかさない。読み手に伝わらない言葉は、具体に戻して言い直す
- 例を並べすぎない。例は読み手の考えを、その例の範囲に狭める
