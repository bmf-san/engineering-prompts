# 論理的思考

考えを、他の人が同じ道筋で追える形にする。問いに対する主張を言い切り、根拠とのつながりを両方向から確かめる。

## いつ使うか

- 説明・提案・設計の考えを組み立てるとき
- 文章や資料の筋が通っているかを点検するとき
- 「何が言いたいのか分からない」「説得力がない」と言われたとき

分け方と並べ方は `structuring`、共通点を抜き出して型にするところは `abstraction`、何を解くかを決めるところは `problem-framing`、根拠が事実として正しいかは `fact-verification`、他人の主張や自分の判断をそのまま受け入れてよいかは `critical-thinking`、文章の表現は `technical-writing` を使う。

## 1. 問いを確かめる

やること:

1. 何に答えるのかを、疑問文で一文に書く
2. 読み手がその問いの答えを求めているかを確かめる。ずれていれば、問いを読み手に合わせて直す

守ること:

- 問いが決まらないうちに主張を書かない。答えの範囲が定まらない

## 2. 主張を言い切る

やること:

1. 問いへの答えを一文で書く。文末まで言い切る
2. 読み手がその主張を受けて何をすればよいかが分かるかを確かめる

守ること:

- 「〜が重要」「〜を検討する」で止めない。何がどうなのか、何をするのかまで書く
- 根拠から言える範囲を超えて主張しない。超えるなら、主張のほうを弱める

## 3. 根拠でつなぐ

やること:

1. 主張を支える根拠を並べる
2. 上から下へ「なぜそう言えるか」、下から上へ「だから何が言えるか」と読み、両方向につながるかを確かめる
3. 読み手と共有していない前提を書き出す。書かれていない前提は、読み手には飛躍に見える
4. 反対の立場から、主張が成り立たない場合を考える。成り立たない条件があれば、主張に条件として書く

守ること:

- 根拠に、事実と解釈を混ぜない。解釈を根拠にするなら、その元の事実も書く
- 根拠の数より、つながりの強さを優先する。弱い根拠を足しても主張は強くならない

## 4. 点検

書き終えたら、次の型に当てはまるところがないかを見る。

| 型 | 見分け方 | 直し方 |
| :--- | :--- | :--- |
| 結論がない | 情報は並んでいるが、「だから何か」がどこにも書かれていない | 一番言いたいことを一文で冒頭に置き、情報をその根拠として並べ直す |
| 問いと答えがずれている | 主張は正しいが、聞かれていることに答えていない | 問いを書き直し、それに答える主張にする |
| 根拠が主張を支えていない | 話題が同じだけで、根拠が正しくても主張は言えない | 「なぜそう言えるか」に答えている根拠だけを残す |
| 前提が隠れている | 書き手には当たり前で、読み手には共有されていない前提に頼っている | 前提を書き出す。読み手が受け入れない前提なら、それ自体を根拠で支える |
| 選択肢を絞りすぎている | 二択で話しているが、ほかの選択肢を検討していない | ほかの選択肢を書き出し、落とした理由を添える |
| 因果と順序を取り違えている | 先に起きたこと、同時に起きたことを原因として書いている | 原因と言えるだけの根拠を足すか、「同じ時期に起きた」と書くにとどめる |
| 言い過ぎている | 「必ず」「すべて」など、根拠が支えきれない強さで書いている | 根拠が支える範囲まで弱めるか、条件を書く |
