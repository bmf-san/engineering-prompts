# 課題整理

解き方より先に、何を解くかを決める。課題を取り違えると、正しく解いても成果にならない。

## いつ使うか

- 相談や依頼を受けて、何が本当の課題かが分からないとき
- 議論がかみ合わない、同じ話を繰り返しているとき
- 解決策から話が始まっているとき（「〇〇を導入したい」）
- 課題が多く、どれから手を付けるかを決めたいとき

原因や問いを分解する軸に迷うところは `structuring`、整理した内容を筋の通った形にまとめるところは `logical-thinking` を使う。原因が一つに絞れない、打ち手が効かずに問題が戻ってくるときは `systems-thinking` を使う。

## 1. 分けて書く

次の 6 つに振り分ける。

| 項目 | 書くこと |
| :--- | :--- |
| 現象 | 観察できる事実。誰が見ても同じになる書き方にする |
| あるべき姿 | どうなっていれば困らないか |
| 問題 | 現象とあるべき姿のずれ |
| 原因 | ずれを生んでいるもの |
| 課題 | 取り組むと決めたこと。原因のうち、自分たちが動かせるもの |
| 解決策 | 課題を解く手段 |

やること:

1. 相手の話や手元の情報を、上の 6 つに振り分ける
2. 解決策として語られたものは、それで何を解きたいのかを確かめて、問題に戻す
3. 誰にとっての問題かを書く。立場が変わると、問題も変わる
4. あるべき姿が書けないときは、関係者の間で目指すものがそろっていないことが、先に解く問題になる

## 2. 原因を掘る

やること:

1. 問題に対して「なぜ」を重ね、自分たちが動かせるところまで掘る
2. 原因の候補を並べ、それぞれを確かめる方法を書く。確かめていない原因は、仮説と書く
3. 原因が複数あるなら、問題に効いている度合いの大きいものを選ぶ

守ること:

- 人に原因を置いて止めない。その人がそうした仕組みや状況まで掘る
- 同じ時期に起きたことを、原因と決めない

## 3. 問いに立て直す

やること:

1. 課題を「何が決まれば前に進むか」という問いの形にする
2. 問いに答えが出せるかを確かめる。何が分かれば答えになるか、誰が決めるかを書く
3. 大きすぎる問いは、答えの出せる小さな問いに割る

守ること:

- 答えの出し方が書けない問いは、まだ課題になっていない。問いを割るか、確かめ方から決める

## 4. 順番と範囲を決める

やること:

1. 課題ごとに、効き目（問題がどれだけ小さくなるか）、手間、急ぐ理由を書く
2. 解く順番を決める。ほかの課題の前提になるものを先にする
3. 解かないものを、理由とともに書く
4. 課題・問い・解かないものを、関係者とそろえる

守ること:

- 現象・原因・解決策を、1 つの文に混ぜない。混ざっていたら分けて書き直す
