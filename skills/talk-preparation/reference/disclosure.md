# 非公開情報の確認

登壇の材料は、所属する組織の内部資料や、関係者との会話から集めることが多い。そこには公開されていない情報が混ざる。話してよいかは「誰から聞いたか」や「どこにあったか」ではなく、公開されているか、持ち主から公開の許可を得たかで判断する。

情報収集の段階で非公開情報を表に挙げ、資料に入れる前に確認する。

## 判断の順序

1. 公開されているか。誰でも読める出典（公式のブログ、プレスリリース、決算資料、過去の登壇資料など）があれば、出典を控える
2. 公開されているなら、公開した範囲を超えていないか。詳しさ、時点、数値の精度を出典と比べる
3. 公開されていないなら、持ち主に公開の許可を取る。持ち主は所属する組織、他の組織、個人のいずれか
4. 許可が取れない、または間に合わないなら、丸める、傾向にする、名前を伏せるで話の筋が保てるかを考える。保てなければ外す

## 観点

| 種類 | 例 | 確認すること |
| :--- | :--- | :--- |
| 事業の情報 | 売上や利用者数、目標値、未発表の製品や機能、取引先 | 公表済みか。数値は公表した精度を超えていないか |
| 組織や開発の内部データ | 人数や体制、開発の生産性の指標、コスト | 公表済みか。丸めた値や傾向で足りないか |
| 障害・インシデント | 日付、影響範囲、原因 | 公表済みか。公表した範囲を超えていないか |
| セキュリティに関わる情報 | 内部のエンドポイント、ネットワーク構成、製品のバージョン、既知の弱点、移行途中の状態 | 攻撃の手がかりにならないか。公表済みの情報でも、組み合わせると手がかりにならないか |
| 意思決定の経緯 | 却下した案、関係者間の意見の対立、組織の事情 | 関係者が、外で話されることに同意しているか |
| 他の組織から得た情報 | 共催先、取引先、ベンダーから聞いた構成や事情、契約の条件 | 先方が公表しているか。NDA がなくても、先方の確認なしに出さない |
| 個人に紐づく情報 | 名前、評価、発言、写真 | 本人の同意があるか |
| 画面や資料への写り込み | スクリーンショット、図の元資料、デモ環境 | ブラウザのタブ、通知、URL、他の利用者のデータが写っていないか |

## 守ること

- 確認が済むまで、資料に入れない
- 公開済みの出典、確認先、確認の結果をページに残す
- 一つ一つは公開済みでも、組み合わせると非公開の事柄が推測できないかを見る
- 質疑や登壇後の会話でも同じ基準で答える。想定問答に「答えないこと」として載せ、答え方を決めておく
- 資料を公開するときは、公開する版で改めて確認する。発表者ノート、非表示のスライド、埋め込んだ元データも対象にする
