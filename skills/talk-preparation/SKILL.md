# 登壇準備

社外イベントでの登壇を、段階ごとに 1 つのページを作りながら準備する。資料を作り始める前に、イベントが求めているものと、自分が足せるものを決めることに重きを置く。

## いつ使うか

- 社外イベントでの登壇が決まったとき（依頼を受けた、CFP が採択された）
- 登壇のテーマを決めたいとき
- 登壇資料や想定問答を作る前に、材料を集めて整理したいとき

CFP を書いて応募するところまでは `cfp-writing` を使う。

## 段階と成果物

段階ごとに 1 ページを作る。ページの雛形は [reference/template.md](reference/template.md) にある。

| 段階 | 成果物 | 決めること |
| --- | --- | --- |
| 1. イベントの把握 | イベント概要 | 持ち時間、質疑の形、聴き手 |
| 2. テーマ決め | テーマ | 一番伝えたいこと、既存の発信に足すもの、話す深さ |
| 3. 情報収集 | 情報収集 | 話す材料、エピソードの候補 |
| 4. アウトライン | アウトライン | 構成と時間配分 |
| 5. スライド構成 | スライド構成 | スライドごとに載せることと話すこと |
| 6. 想定問答 | 想定問答 | 答え方 |
| 7. 発信の後追い | 記事など | 書くかどうか |

親ページに、段階・期限・状態の表と、各ページへのリンクを置く。ページには、資料を作るのに使う情報だけを書く。

## 1. イベントの把握

やること:

1. 日程、形式、持ち時間、質疑の受け方を書く
2. 依頼の理由（なぜ自分に声がかかったか）を写す。CFP なら、採択された提案の要旨を写す。既存の記事や発表がきっかけなら、それがテーマの起点になる
3. 主催が想定する聴き手と、それぞれに持ち帰ってほしいものを表にする

## 2. テーマ決め

やること:

1. イベントのテーマと依頼の理由から、キーワードを抜き出す。キーワードごとに、意味と出どころを書く
2. 既存の発信がきっかけなら、そこに何を足すかを決める。足すものが無い話は、話す価値が薄い
3. 一番伝えたいことを一文で決める。各節がそれをどう支えるかを言えるようにする
4. 話す深さを決める。技術の詳細まで話すのか、判断の理由までにとどめるのか

守ること:

- 既存の記事や発表の再演にしない。聴き手の一部はすでに読んでいる
- イベントが「意思決定」や「苦労」を主題にしているなら、成功談だけで構成しない。判断を変えたこと、揺れたこと、進め方を切り替えたことを候補にする

## 3. 情報収集

やること:

1. 出典の表を作る。資料名と場所（URL やローカルのパス）を並べる
2. 時系列の表を作る。時期を確かめられなかった出来事は「時期は未確認」と書き、推測で埋めない
3. テーマのキーワードごとに材料を並べる。主張を太字で書き、根拠を続ける
4. 既存の発信がきっかけなら、そこに書かれていないことを抜き出す。テーマ決めの「足すもの」の材料になる
5. エピソードの候補を表にする。判断を変えたこと、うまくいかなかったこと、苦労したことなどを、中身と出典とともに書く。どれを話すかはアウトラインで決める
6. 数字や時期は、資料に書く前に一次ソースで確かめる。手順は `fact-verification` を使う

守ること:

- 材料を集める段階で、話す内容を決めない。決めるのはテーマとアウトライン

## 4. アウトライン

やること:

1. 持ち時間から、節ごとの時間を割り振る
2. 見出しだけを読んで、全体の流れと持ち帰ってほしいことが分かるかを確かめる。文章の観点は `technical-writing` を使う
3. 各節が、一番伝えたいことをどう支えるかを書く

## 5. スライド構成

実際のスライドは人が別に作る。この段階では、スライドごとに何を載せ、何を話すかまでを作る。

やること:

1. アウトラインの節を、スライドに割る。1 枚で伝えることは 1 つにする
2. スライドごとに、見出し、載せること（文、図、数字、コード）、話すこと、時間を書く
3. 節の変わり目のスライドには、次の話へつなぐ一言を書く。つなぎの言葉が見つからないときは、話の順番を見直す
4. 時間を合計し、持ち時間より短く収まるように枚数を絞る。本番は予定より長くなる
5. 載せる前に、非公開情報でないかを確かめる。判断の順序と観点は [reference/disclosure.md](reference/disclosure.md) にある

守ること:

- 載せることは短くし、説明は「話すこと」に回す。聴き手は読みに来ているのではなく、聴きに来ている
- 話すことは要点だけにする。読み上げる原稿にしない
- デザインや体裁は決めない。それはスライドを作る人が決める

## 6. 想定問答

やること:

1. 質疑の形（セッション直後か、パネルでまとめてか、事前に集めるか）を確かめる
2. 聴き手ごとに、聞かれそうな質問を挙げる
3. 非公開情報を聞かれたときの答え方を決めておく

## 7. 発信の後追い

やること:

1. 登壇の内容を記事にするかを決める。時間の都合で削った話や、資料だけでは伝わらない判断の理由があれば候補になる
