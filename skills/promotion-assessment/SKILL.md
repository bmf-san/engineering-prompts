# 昇格の推薦と判定

一つ上の等級の要件を物差しにして、メンバーがどこまで満たしているかを根拠付きで見立て、推薦の結論と、期末に何を確かめれば判定できるかを書く。

## いつ使うか

- 期初に、メンバーを昇格候補として推薦するとき
- 期末に、昇格の判定の材料をそろえるとき

期ごとの評価は `member-evaluation` を使う。

## 入力

- 一つ上の等級の要件。元の要件の一覧（マスタ）から引く
- 組織の昇格の目安。充足度の閾値、推薦の区分、判定の手続き
- 本人のスキルマップと自己評価
- 本人の活動。PR、文書、チャットの発言、日々の記録
- 組織の推薦フォーマット。あればそれに従う

## 1. 物差しを決める

やること:

1. 一つ上の等級の要件を、元の一覧から写す
2. 組織の昇格の目安を確かめる。充足度の閾値と、推薦の区分

守ること:

- 要件は入学要件として扱う。現在の等級の期待を満たしているかとは分けて見る
- スキルマップなどに写された要件の文は古いことがある。元の一覧で確かめる

## 2. 項目ごとに見立てる

やること:

1. 要件の項目ごとに、到達を見立てる。本人の自己評価と、自分で確かめた事実の両方を使う
2. 項目ごとに、根拠になる実案件を挙げる
3. 項目ごとの充足度と、全体の充足度を出す

守ること:

- 根拠の成果物は、作成者と時期を確かめる
- 「できる」と「している」を分ける。一度できたことと、繰り返し発揮していることは違う

## 3. 推薦を書く

やること:

1. 結論を書く。推薦の区分と充足度、中核の要件を実案件で示しているか
2. 満たしていると判断した根拠を、項目ごとに書く
3. 満たしていない項目ごとに、現状と、期内に確かめられる期待を書く
4. 判定の観点を書く。観点ごとに、期末に確かめる材料を挙げる
5. エビデンスを、全体・項目別・補足に分けて並べる

守ること:

- 充足度の閾値は目安として扱う。数字だけで結論を出さない
- 期待は、期内に確かめられる大きさにする

## 4. 期末に判定する

やること:

1. 判定の観点ごとに、期末に確かめる材料を開いて確かめる
2. 満たしていなかった項目が、期待どおりに埋まったかを見る
3. 判定の案と理由を書く。見送るなら、次に確かめることを書く

守ること:

- 判定は評価者と組織の手続きで決める。この skill は材料と案までを作る
- 推薦と判定の資料は、評価者と推薦に関わる人だけが見る場所に置く。本人に伝える内容と範囲は、組織の決まりに従う
