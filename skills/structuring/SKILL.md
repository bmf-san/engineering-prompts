# 構造化

情報や考えを、目的に合った軸で分けて並べ、全体と部分の関係が一目で分かる形にする。

## いつ使うか

- 情報が多く、どう分ければよいか迷うとき
- 目次・資料の章立て・一覧表を作るとき
- 問題や目標を、手をつけられる大きさまで分解するとき
- 作った分類や章立てが分かりにくいと感じたとき

主張と根拠のつながりは `logical-thinking`、共通点を抜き出して型にするところは `abstraction`、何を解くかを決めるところは `problem-framing` を使う。

## 1. 目的を決める

やること:

1. 何のために分けるかを一文で書く。誰が、分けた結果を見て何をするのか
2. 分けた結果をどこで使うかを決める。目次、比較表、担当の割り振り、原因の絞り込みなど

守ること:

- 目的が決まらないうちは分け始めない。軸を選ぶ根拠がなくなる

## 2. 軸を選ぶ

やること:

1. 目的に効く軸を選ぶ。よく使う型は次の 4 つ
   - 要素: 構成するもので分ける
   - プロセス: 時間や手順で分ける
   - 対になるもの: 内と外、量と質、事実と解釈など
   - 2 軸: 2 つの軸の組み合わせで分ける
2. 候補の軸が複数あれば、それぞれで分けてみて、目的に一番効くものを選ぶ

守ること:

- 1 つの階層には 1 つの軸だけを使う

## 3. 分解する

やること:

1. 上から下へ分ける。一段下がるごとに、上の項目を同じ軸で分ける
2. 問題を分解するなら「なぜ」で、解決策を分解するなら「どうやって」で掘る
3. 手をつけられる、または判断できる大きさになったら止める
4. 同じ階層に並べる数を絞る。多ければまとめて、一段上の項目をつくる

守ること:

- 網羅を目的にしない。目的に効かない枝は落とす
- 抽象度の違うものを、同じ階層に並べない

## 4. 形を選ぶ

やること:

1. 見せたいものに合わせて形を選ぶ
   - 木（箇条書きの入れ子、ロジックツリー）: 全体と部分の関係を見せる
   - 表: 複数の項目を、同じ観点でそろえて比べる
   - 2 軸の図: 2 つの観点の組み合わせで位置づける
   - 順番の並び: 手順や時間の流れを見せる
2. 表にするなら、行と列のどちらに何を置くかを、読み手が比べたいものから決める

## 5. 点検

分け終えたら、次の型に当てはまるところがないかを見る。

| 型 | 見分け方 | 直し方 |
| :--- | :--- | :--- |
| 軸が混ざっている | 同じ階層に、別の軸で分けた項目が並んでいる（例: 手順と担当者が同じ列にある） | 軸を 1 つに決め、ほかの軸の項目は別の階層か別の表に移す |
| 抽象度がそろっていない | 同じ階層に、大きな話と細かな話が並んでいる | 細かい話を、それを含む大きな項目の下に移す |
| 「その他」が大きい | 分類に収まらない項目が多い | 分ける目的に戻り、軸を選び直す |
| 重なっている | 1 つの項目が、同じ階層の 2 か所に入る | 境界を定義し直すか、軸を選び直す |
| 漏れている | 目的から考えて当然あるべき項目がない | 軸の反対側（内に対する外、量に対する質など）を書き出して確かめる |
| 深さがそろっていない | 一部の枝だけが深く、ほかは浅い | 深い枝が目的に効いているかを確かめる。効いていなければまとめる |
