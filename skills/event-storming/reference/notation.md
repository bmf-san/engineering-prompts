# 付箋の種類と並べ方

## 付箋の種類

色は一般的な割り当て。手元の付箋に合わせて変えてよいが、凡例を貼って全員でそろえる。

| 種類 | 色 | 書くこと | 例 |
| :--- | :--- | :--- | :--- |
| ドメインイベント | オレンジ | ドメインで起きた出来事。過去形 | 注文が確定した |
| コマンド | 青 | 出来事を引き起こす指示や操作。命令形 | 注文を確定する |
| アクター | 黄（小） | コマンドを実行する人や役割 | 購入者 |
| ポリシー | 紫 | 出来事を受けて起きる決まった反応。「〜したら、〜する」 | 支払いが完了したら、出荷を指示する |
| リードモデル | 緑 | 判断に使う情報 | 在庫の一覧 |
| 外部システム | ピンク | 関わる外のシステムやサービス | 決済サービス |
| 集約 | 黄（大） | 同じルールで守る、出来事とコマンドのまとまり | 注文 |
| ホットスポット | 赤 | 疑問、食い違い、痛み、未確認のこと | 返品の期限は誰が決める？ |

## 並べ方

- 時間は左から右に流す
- 同時に起きる出来事、並行して進む流れは、上下に並べる
- 粒度ごとに使う付箋を増やす
  - ビッグピクチャー: ドメインイベント、ホットスポット、アクター、外部システム
  - プロセスモデリング: 上に加えて、コマンド、ポリシー、リードモデル
  - ソフトウェア設計: 上に加えて、集約
- プロセスモデリングでは、次の順でつながる形を基本にする

  ```text
  リードモデル → アクター → コマンド → (集約 / 外部システム) → ドメインイベント → ポリシー → コマンド …
  ```

## 書き方の決まり

- ドメインイベントは「名詞 + 過去形の動詞」で書く。「〜した」「〜された」
- 一枚に一つの出来事だけを書く
- 業務で使う言葉で書く。画面やテーブルの名前で書かない
- 同じ出来事に別の書き方が出たら、どちらかに寄せる前に、本当に同じものかを確かめる
